Detailed Description

Where the pixel grid and the network sit inside the window.

The window is twice as wide as it is tall, which leaves a square region on the left for the paintable grid and a square region on the right for the network visualization. Every bound is in normalized device coordinates, where the window spans [-1, 1] on each axis.

◆ INPUT_COLUMN_SHARE

constexpr float shared::INPUT_COLUMN_SHARE {0.32f}
inlineconstexpr

The aspect ratio has to divide the height exactly.

Otherwise the width would round and the window's true aspect would no longer match WINDOW_ASPECT, which would quietly stretch everything drawn in NDC. The share of the diagram's width given to the input layer.

The input is drawn as a 28 by 28 image, so it needs to be wide enough to read as a digit, while the hidden layers only need room for a column of dots.

◆ WINDOW_ASPECT

constexpr float shared::WINDOW_ASPECT {2.0f}
inlineconstexpr

How many times wider the window is than it is tall.

NDC spans [-1, 1] on both axes regardless of the window's shape, so one NDC unit covers twice as many pixels horizontally as it does vertically. Anything meant to look square has to be stretched by this factor along y.
